# Web Push implementation plan

**Goal:** Life OS reminders on each subscribed device without Telegram.
**Spec:** `docs/superpowers/specs/2026-10-01-web-push.md`
**Execution:** inline, as explicitly requested by the user; one Web Push implementation commit after verification.

1. Add independent tests for subscription validation, authenticated API behavior, per-device delivery/retry/expired subscriptions, reminder source filtering and service-worker events; run them against missing behavior.
2. Add `web-push`, subscription/delivery schemas and additive `0004_web_push.sql`; implement PostgreSQL storage with recoverable per-device claims.
3. Implement server-only VAPID configuration/transport, protected subscription and test routes. Validate allowed provider URLs and same-origin mutations.
4. Implement task/Google reminder sources and a non-overlapping startup scheduler, explicitly enabled by Fly runtime environment, sharing the existing database pool.
5. Add a public service worker, stable manifest identity, notification controls and navigation. Handle permission denial, unsupported browsers/iPhone browser mode, subscription resync/key rotation, disable and provider failure.
6. Document secrets/setup and manual physical-device verification. Check migration idempotency in a disposable database, browser controls/worker, focused tests, full tests, typecheck, lint and production build. Review the final diff and commit only Web Push files.

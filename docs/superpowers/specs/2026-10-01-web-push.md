# Life OS Web Push

User-authorized implementation: replace Telegram reminders with Life OS notifications on MacBook and iPhone. The app remains running on Fly. Calendar changes are separate and must not enter either requested commit.

Use standards-based Web Push with VAPID, a root service worker, per-device subscription controls and a test button on `/notifications`. Link the page from the task navigation. iPhone users add Life OS to the Home Screen, then enable notifications from the installed app; permission requests only follow a button click.

Store subscriptions and reminder delivery history in PostgreSQL using an additive unified migration. Deduplicate by subscription, source identifier, start time and lead; success on one device must not suppress another. Retry failed attempts inside the reminder window and delete subscriptions on HTTP 404/410. Use a recoverable lease so an interrupted send does not permanently lose a reminder. Delivery is at least once: a crash after provider acceptance and before the success update may duplicate a message.

Validate subscriptions, restrict endpoints to Apple, Google and Mozilla push providers, require the existing access session and same-origin requests for mutations. Keep private VAPID keys exclusively in server environment variables. The public service worker serves no cached private pages, always displays a visible push notification and only navigates within the app origin.

Reuse task date semantics and the Google Calendar integration. Timed action dates, due dates and selected timed Google events receive reminders 30, 15 and 5 minutes before starting. Skip done/canceled tasks, date-only entries and canceled/all-day Google events. Poll every minute in the existing Next server process; never overlap ticks, bound external request times, and skip provider work without active subscriptions. Start only when explicitly enabled and VAPID is configured; builds and normal local development must not send reminders.

Maintain the existing always-running single Fly Machine and volume. Do not deploy or change production resources as part of the requested local implementation/commits. Document key generation, Fly secrets, iPhone setup, actual-device verification and the observed tight 256 MB limit. Keys must remain stable across deployments.

Acceptance: subscription enable/disable/test works, unauthorized and invalid requests are rejected, service-worker push/click behavior is verified, independent-device delivery and retry/expiry behavior pass tests, database migration is retry-safe, browser UI works at phone widths, typecheck/lint/full unit suite/build pass. Actual phone delivery requires deploying the code, configuring VAPID secrets and enabling notifications on each physical device; automated testing must not claim that physical-device delivery was verified.
